## Trigger

Follow-up to the same day's N-12 fix. User: the honest side of the battery
needs more non-trivial "green" scenarios — honest mistakes, legitimate
gradual improvement, gradual semantic drift approved by humans, and external
shock — and asked for a feasibility/consequences discussion before deciding
scope.

## Done

- Explored the scenario/`SimConfig`/oracle architecture via a subagent to
  ground the discussion in what actually exists (full scenario taxonomy,
  `SimConfig` field list, drift/capability mechanics, honest-scenario
  false-negative numbers already measured).
- Discussed feasibility of all four candidates:
  - **Honest mistakes** — low-medium effort, no existing mechanic for
    *bursty/correlated* errors (only i.i.d. `responsiveness`).
  - **Legitimate gradual improvement** — medium effort; no existing
    "value ramps over the episode" knob (closest existing thing,
    `hidden_capability`, is growth that's hidden and misused — needed the
    honest mirror, not a relabel).
  - **Approved gradual semantic drift** — feasible in a cheap form
    (transparency + harmlessness, reusing `silent_ground_drift` with low
    `display_bearer_inertia`), but flagged a real gap: no channel models
    actual human sign-off today. Checked directly — `board_rule_signal` is
    not a governance signal, it's a verbatim copy of `correction_request`
    (`observation.py:285`).
  - **External shock** — user's own instinct that this is hardest confirmed
    and sharpened: every existing detector is a structural pattern-matcher;
    "was overriding correction proportionate to a real emergency" is a
    normative cost-benefit judgment none of the current oracle logic can
    make. Argued this may need a different (graded/utility) evaluation
    methodology rather than a fifth scripted scenario.
- User decided scope: build the first two plus drift under the cheap
  (transparency + harmlessness) definition now; defer the explicit
  approval-signal channel into the Phase 1+ goal-driven-agent refactor
  (natural fit: a board actor's `sign_off` action); defer `external_shock`
  entirely, to be revisited only after Phase 1+.

## Decisions

- Treated "approved" drift's cheap definition as *transparency + harmlessness*,
  explicitly not consent, and said so in the doc rather than letting the
  scenario name imply more than the mechanism models — a critic-facing
  honesty point, not just a scoping one.
- Deferred the approval-signal channel to Phase 1+ rather than bolting it
  onto Phase 0.5, because modeling genuine sign-off needs an actor with a
  goal policy to issue it meaningfully (Phase 1+ machinery), not a new
  scripted flag on top of `SimConfig`.
- Deferred `external_shock` past Phase 1+ entirely rather than attempting a
  scoped-down scripted proxy now, on the grounds that a proxy which only
  tests "was the deviation temporary" would misrepresent what "trading
  risks" actually requires.
