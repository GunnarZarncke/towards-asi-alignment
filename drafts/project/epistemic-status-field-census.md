# Epistemic-status field census and cross-chapter duplication report

Generated by hand (with subagent assistance for body-text spot checks) on 2026-07-17, in
response to: "many epistemic status notes mention the same topics again and again ... create a
census of the fields referenced in each chapter (merging subfields) and then read chapters that
share topics for duplication and report."

Source: the `\begin{epistemicstatus}...\end{epistemicstatus}` box near the top of each chapter
(`chapters/ch*.tex`) and appendix (`appendices/app*.tex`). 55 boxes exist across 62 files; 7
appendices have none (appA, appE, appH, appI, appJ, appK, appL — mostly reference/template
material with no independent claims to calibrate).

This report has two parts:

1. **Census** — every field/literature name in each chapter's epistemic-status box, merged into
   ~25 top-level fields (subfields folded in, e.g. "apprenticeship learning" + "CIRL" + "inverse
   reward design" → **Reward-inference**).
2. **Duplication check** — for fields referenced by 3+ chapters, whether the *chapter bodies*
   (not just the one-paragraph epistemic-status disclosure) actually re-explain the same
   background concept from scratch each time, versus explaining it once and reusing/cross-
   referencing it. Spot-checked via four parallel sub-agent passes over the highest-fan-out
   clusters (see "Duplication findings" below); the per-chapter table below is a manual read of
   the epistemic-status text only and did not by itself require re-reading chapter bodies.

### Terminology note (not duplication, but reader confusion risk)

"Bottleneck" is overloaded: information-bottleneck (ch15/17/21) vs. correction-channel
weakest-link capacity (ch22/24/26/14). Consider a one-line disambiguation footnote somewhere
in the value/correction arc, not a merge.

## Overall pattern and recommendation

**Epistemic-status boxes vs. body text are different problems.** The boxes repeat field names
across many chapters because each chapter honestly discloses its background literatures — that
is expected and mostly fine, especially for neighboring chapters in the same arc (value bundle
ch15–ch21 all cite IRL/IB; correction arc ch25–ch29 all cite corrigibility literature). The
audit's actionable findings are narrower: **~8 body-text sites** where the same canonical
sentence, formula, or rhetorical setup is re-derived from scratch without a cross-reference,
sometimes with inconsistent variants (Markov-blanket conditioning; IRL bound; Goodhart one-liner;
κ/Hamilton).

**Recommended editorial pass (in priority order):**

1. Fix the three **high-priority** pairs above (ch36→ch34, ch35→ch13, ch06/ch07→ch01) — these
   are pure waste and one (Markov blanket) has a real inconsistency bug.
2. Trim the **medium-priority** IRL bound triplication (ch04/ch15→ch17) and CEV clause (ch45→ch04).
3. Add **soft cross-refs** for the personal-identity rhetorical device (ch18/ch31→ch08) and
   ch47→ch18 — cheap, preserves self-containedness while signaling intentional reuse.
4. Leave epistemic-status boxes alone for now unless a future pass wants to shorten them to
   "background: see chNN" for chapters that add no new field (e.g. ch17/ch20/ch21's explicit
   "same as previous chapter" notes could become one shared appendix paragraph — optional, lower
   priority than body trims).

**Model chapters** (already doing it right): ch16→ch17 for IRL bound, ch25→ch28 for CEV,
ch37→ch13 for percolation ("inherit rather than re-derive"). Use these as the template when
trimming the flagged pairs.
