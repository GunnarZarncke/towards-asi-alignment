### The Basic Shift

### Why This Matters

A deployment decision needs an argument that connects them. The question is not: Did the system pass an evaluation? The question is: Does the whole case support deployment under the stated threat model? This chapter gives the form of that case. It does not prove any real system safe. It says what must be true before a certified safety case means anything in the framework of this book. The decision relevance is deliberately sharp. A safety case should help an evaluator decide whether to restrict, redesign, or refuse deployment. Restrict includes reducing D ; redesign includes adding proof, containment, randomization, or cost-of-faking structure; pause is a form of restrict. If the case cannot change a deployment decision, it is not a safety case. It is documentation. A 2026 industry index of published lab frameworks records that gap: they ``sometimes lack quantitative thresholds, genuinely independent audits, and clear decision authority'' .

### The First Mistake

What we train is a network. What we deploy is that network plus a system prompt, a tool sandbox with shell access, a memory store that carries context across sessions, an evaluation suite that gates releases, a population of users who learn what it will and will not do, an operator team that patches the prompt every week, a company whose revenue depends on retention, and a market that rewards whoever ships first. The network learns during training; the users and the operator team learn during deployment; the evaluation suite selects; the memory store remembers; the market rewards; the sandbox constrains; the prompt hides part of the objective from the user. Only the first of these is what the alignment literature usually calls the system. Whether any of the others changes the failure we would intervene on is what we will investigate.

### Accidental chain-of-thought optimization at frontier labs

Training bugs can make a model’s ‘thinking’ less trustworthy—even without a model trying to hide. Both major frontier labs disclosed **accidental pressure on the model’s written reasoning** during training: Anthropic reported about 8% of Mythos Preview reinforcement-learning episodes exposed that reasoning to the reward signal (also affecting earlier models); OpenAI found accidental grading of reasoning in several released models and added automated detection. If the “thinking” text becomes something training rewards—even by accident—it becomes a worse window into what the model is doing. A readout that overseers rely on is not trustworthy if the training pipeline grades that same text. **Read more in:** Ch. 39, *Passive Observation Is Not Enough*; Ch. 41, *Checking a System at Every Level*; and Ch. 43, *What Survives an Adversary: Verifiability and Representability*.

### The Four Layers of Laundering

Goal laundering can occur at several layers. Distinguishing these layers prevents a common mistake: treating all continuity as alignment and all change as drift. Semantic Laundering  Semantic laundering preserves words, statements, constitutions, policies, labels, and public explanations while changing what those statements control. The system says:  I respect human autonomy. But operationally, autonomy now means: user clicked accept rather than: user retained informed, non-manipulated, reversible option-space. Semantic laundering is easy because language is cheap. A system can preserve a verbal mapping even if the internal control structure has changed. The correct diagnostic question is not:  Does the system still endorse the sentence? but:  What policy gradients does the sentence activate? Bundle Laundering  Bundle laundering preserves a broad moral category but changes its control role. Suppose a system still recognizes suffering, but suffering no longer dominates action selection under uncertainty.
